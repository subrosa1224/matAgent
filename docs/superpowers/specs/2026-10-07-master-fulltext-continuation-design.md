# 主控任务中的全文预览、详细分析与实验统计接续设计

日期：2026-10-07。类型：架构级流程衔接。

状态：用户已确认交互规则、待审核数据试运行默认方案，并以“按设计实施”批准实施。本设计描述的是目标架构，不等于全部已运行能力；目前已实现安全附件与任务持久化、主控及网页/CLI 接续入口、来源核验预览、新提取快照与 pending/trial 交接，以及第五阶段 A 的范围门槛、真实隔离描述统计与部分分区报告。比较/趋势分析、关键条件绑定和实际网页完整验收尚未完成，详见实施计划与阶段报告。

## 1. 已确认的用户体验

单独阅读论文仍保留“上传 → 预览 → 根据用户需求详细分析”。完整科研任务由主控记住原问题和分析需求：取得对应全文后先预览，需求明确且没有关键歧义时自动继续详细分析、实验统计和汇总；不要求用户重复说“深度分析”。缺少全文、缺少分析目标或存在会改变研究结论的关键歧义时，才询问用户。

端到端可以跨多轮完成。等待上传不丢失原任务，补充文件后接续未完成阶段，不重新执行已经完成的数据库查询，也不把文献摘要当作实验测量。

通过原文、样品绑定与条件检查的待审核记录可以参与试运行。保留 pending 状态，报告明确标注“待审核、仅供试运行”；不得自动批准、进入已批准知识数据，或宣称专家已验证。数据来源检查不等于材料专业正确性验证。

## 2. 范围与方案选择

选用：主控保留持久化任务，调用文献阶段适配器，再通过有来源的测量交接调用数据分析 Agent。网页只负责接收输入、注册附件和显示进度，不自行完成跨 Agent 编排。

另一个可用方案是维持人工操作：用户预览、深度分析、保存主题报告，再另行触发主控的证据复用。这可继续作为单独文献模式，但不能验收为主控任务的自动接续。

不选用无条件的上传即全量深度分析：无主题上传、明确只要预览、对象歧义以及不相关论文不应被自动升级为昂贵分析。也不依赖网页识别特定口令来决定端到端任务的后续步骤。

本阶段只接通已有材料数据库、文献与数据分析能力。不新增实验数据库 Agent、付费全文下载、专业正确性自动裁决、通用后台任务调度或无限 Agent 协商；不修改数据库筛选条件、文献检索排序和已有正式审核规则。

## 3. 设计前基线依据与实际缺口（v18）

- `cli._open_master_runner` 当前对文献子 Agent 关闭 RAG，正常主控工具表缺少全文摄取、检索和提取工具。
- `MasterAgentRunner.ask/ask_stream` 当前没有附件引用参数，主控 checkpoint 没有结构化的待接续全文任务。
- `unified_ui_gradio._dispatch_core` 当前将自动模式的 PDF 直接发给独立文献聊天分支，不接续主控。
- 文献聊天上传分支依赖“深度分析”等措辞；详细分析默认的 `batch-analyze` 未要求提取实验矩阵。
- `ArtifactRegistry` 当前在内存中保存附件索引；仅保留会话里的 Artifact ID，不能保证重启后恢复路径。
- `EvidenceAwareLiteratureRunner` 复用完全同题的已保存报告，适合旧证据复用，但不是本轮附件提取入口。
- 正式 `literature_matrix_to_analysis` 要求人工批准；现有 `LiteratureEvidenceTrialService` 有保守的 pending 试运行路径，但依赖保存报告，不能直接承担当前附件任务。

上述结论来自 v18 路由诊断，不代表提取器或统计器自身已被证明错误。诊断中的观察器只记录分支，未执行真实全文分析。

## 4. 责任和入口

### 主控

保存原始问题、分析范围、当前阶段及结果引用；决定何时询问、继续或降级；检查领域输出；安排数据分析；生成分来源的汇总。模型可以提出计划，但文件授权、阶段转移、证据门槛和数据审批不能由模型文本直接改变。

### 文献阶段适配器

复用现有 PDF 解析、索引、预览、档案与矩阵提取服务，返回结构化预览或提取结果。独立文献模式和主控模式共享服务，不复制两套提取逻辑，不通过拼接 CLI 指令模拟 Agent 交接。

### 数据分析交接与 Agent

适配器将证据检查后的记录注册为专属数据集，交给已有数据分析 Agent。数据分析阶段只能引用该任务明确选定的数据集，不能使用“最近一次报告”或其他主题的数据替代。正式已批准路径与试运行路径分开，不能通过伪造 approved 标签调用正式接口。

### 网页与 CLI

显式文献模式保持独立使用。自动模式中，有活动全文任务时，将新 PDF 的安全引用交给同一个主控会话；没有活动任务且仅上传文件时，仍默认独立预览。CLI 可以通过新增的有界附件引用入口接续同一任务，原无附件调用保持兼容。

同一条消息同时提出完整科研任务并上传 PDF 时，先创建主控任务再绑定附件，不能按“没有旧任务”退回独立预览。仍执行原问题要求的数据库/计算属性阶段，再使用本次附件进入文献阶段。只有阅读论文的请求则使用独立文献路径，不能仅因包含“分析”一词创建完整科研任务。

## 5. 持久化任务与安全附件

新增严格的全文任务记录，保存在现有主控 checkpoint 机制中。至少包含：

- task_id、conversation_id、任务版本、创建和更新时间；
- 不变的原始科研问题，以及用户后续明确补充的需求；
- 目标材料/样品范围、必需指标、不可合并的条件和请求的分析类型；
- 是否已明确要求详细分析、是否只要预览、试运行政策；
- 阶段、附件 ID、document_id、用户选择和预览决定；
- 既有数据库查询与计算属性分析的引用；
- 提取尝试与快照 ID、数据集 ID、统计结果 ID、报告 ID；
- 缺项、隔离记录、澄清理由和失败阶段。

网页只持有任务与附件引用，不以浏览器传回的原问题、阶段或审核状态覆盖服务器记录。活动任务唯一时“继续”接续该任务；出现多个可能任务且未指定对象时，询问用户。用户显式切换主题创建新任务，不能自动沿用旧文献选择。

附件注册在服务器保存可持久化索引，记录哈希、类型、安全显示名、所属会话与受控存储引用。解析真实路径时重新检查会话授权、所属目录、文件存在性和哈希。重启后仅恢复有效引用；未知、跨会话、路径越界或内容改变的引用必须拒绝，不扫描任意目录猜测文件。

主控入口拟新增可选 artifact_refs 和 task_id 参数，默认空值保持现有调用兼容。路径仅由服务器的注册器解析，不进入模型参数或公开页面。空消息但包含有效 PDF 引用时，允许接续已有待全文任务；没有活动任务则按无主题上传处理。

## 6. 阶段和恢复规则

任务保留独立阶段，不以 Agent 的一次 completed 输出推断整个任务完成。

| 阶段 | 接收内容与动作 | 后续阶段 |
|---|---|---|
| waiting_fulltext | 展示候选与全文缺口，等待安全附件或选择 | previewing |
| previewing | 核验论文身份、样品范围、研究方法和指标线索 | extracting、awaiting_clarification 或 reporting |
| awaiting_clarification | 说明会改变分析范围的歧义，等待有针对性的选择 | 依已保存上下文恢复对应阶段 |
| extracting | 按原任务生成档案与实验测量，执行来源和绑定检查 | analyzing 或 reporting |
| analyzing | 对本任务合格数据做条件隔离分析 | reporting |
| reporting | 汇总各来源、覆盖情况与未完成事项 | finished |
| ready_to_resume | 到达调用/时间预算或用户取消后的安全停止点 | 用户继续后恢复未完成阶段 |
| failed | 记录失败阶段及可恢复原因，保留已成功部分 | 明确重试后恢复该阶段 |
| finished | 保存任务级结果，允许进一步询问或明确新任务 | 不自动重跑已完成步骤 |

waiting_fulltext、awaiting_clarification 是需要信息；ready_to_resume 是执行预算或取消，不假称缺少科研信息。模型连接、PDF 解析或数据库故障不要求用户改写明确的科研问题。

遵守已有模型、子 Agent、批次和数据大小限制，不在本阶段提高上限。每个已完成阶段在启动下一阶段前持久化引用；超过本轮预算则保存进度并清楚提示可继续，不静默开启额外后台运行。部分论文成功时保留其结果，但报告不得把剩余论文记作已处理。

用户新指令“只预览”“暂不详细分析”“只分析第2篇”优先于之前的自动续行许可。取消后不再启动新模型请求或下一阶段；已完成的不可变结果保留。

## 7. 预览后的决定

预览输出包含论文身份、研究对象、方法、指标线索、证据引用、相关性与范围风险。预览摘要不进入数值统计，缺少摘要中的某个指标也不能证明全文没有该指标。

- 原任务已要求详细提取，论文身份与样品范围合理，没有关键歧义：自动做针对性详细分析。
- 用户只要预览或没有明确深入分析目标：展示预览，等待用户需求。
- 有原文证据表明材料或方法不满足硬条件：列为背景或排除，不自动用来支持目标结论；其他合格论文继续。
- 论文身份、样品对象或用户选择存在无法安全决定的歧义：说明具体歧义后询问。
- 预览只有指标“可能存在”的线索：可以继续全文核对，不能提前承诺会提取到数值。

用户明确选择范围时遵守选择；需求明确但尚未选择时，分析当前用户提供批次中预览合格的论文，显示入选及排除原因，不从历史全库自动追加论文。

## 8. 提取快照、复用与旧数据保护

详细分析既要形成可阅读档案，也要显式执行任务所需的实验矩阵提取；不能将“生成论文总结”视为测量提取已完成。使用现有通用提取器及其证据门槛，不针对三个开发 PDF 硬编码数值或样品答案。

每次提取尝试产生独立、不可变的结果快照，保存论文哈希、片段来源、提取器/模式版本、任务指标政策、尝试时间、批次结果、警告与保留/隔离记录。主控持有该快照引用，不把数据库中同一 document_id 下全部历史 pending 记录混成本轮结果。

已有一致哈希、提取版本和任务需求兼容的成功快照可以复用；复用前重新验证来源和所需记录，显示原时间和本次复用标记。需求变更或必需指标不覆盖时，只能报告缺项或执行新的提取尝试，不能修改旧快照填补缺项。失败/部分尝试以新尝试 ID 重试，保留父尝试引用；同一个已经成功的阶段重入不得重复登记记录或再消耗模型请求。

新主控提取默认先写任务级快照，不调用会覆盖既有声明/证据链接的批量保存路径。原 approved、pending、rejected 矩阵、档案和审核记录保持不变。论文索引可以正常新增缺失文档，但不改写已有同哈希源片段；本阶段不自动审核或发布新矩阵。

## 9. 测量交接与试运行隔离

每条可交接记录至少保存 document_id、提取快照 ID、测量/样品组 ID、材料与对照角色、指标、原始值、数值及其推导类型、单位、制备变量、测试条件、方法、原文引文、片段 ID/哈希、页码和审核状态。未知项显式保留，不用主题要求补成论文事实。

进入统计前检查：

1. 片段与当前 PDF 身份一致，引文确实存在于该片段且页码有效；
2. 样品及测量绑定成立，不把引用的先前工作、背景常数或其他对照当作主样品；
3. 数值和单位有来源支持，无伪造、重复计数或未解决冲突；
4. 指标属于本任务，必需条件满足该分析用途。

不满足来源、样品绑定或数值检查的记录隔离，不登记为统计输入。测试条件缺失但数值本身可靠的记录，可单独列示；不得与条件明确的记录合并或参与条件依赖的比较。完整性不足时保留缺项报告，不以空表生成假统计。

试运行数据集带 analysis_mode=trial、原 review_status、task_id、快照引用与警告。复用现有试运行证据检查逻辑，但将其拆成可接收显式快照的共享门槛，不要求先构造与原问题文本完全相同的保存报告。

正式已批准数据交接继续要求人工批准。试运行不会改变原矩阵状态、不会写入已批准知识数据，也不会自动消除专业审核需求。已批准记录同样要检查当前来源与任务匹配，不能因 approved 状态跳过源文件完整性检查。

## 10. 条件隔离的统计边界

数据库计算属性与论文实验测量使用不同数据集和来源标记。复合样品、器件及硅基限域实验不自动映射到某个 MP 纯相结构，不把论文性能归给数据库候选。

基础描述统计按论文、样品、指标、单位、测量方法和测试条件划分，保留制备变量。比较或趋势分析另行建立可比集合：只允许任务指定的自变量改变，污染物、光源、测试时间、偏压等关键测试条件必须明确且可比；未知不等于相同。跨论文默认分别展示，本阶段不做跨论文综合排名。

例如负载比例可以是待分析自变量，不应因比例不同而永远无法比较；但不能把不同光源或污染物下的降解率合并成负载趋势。XRD 描述与穆斯堡尔定量即使都谈物相，也不合并为同一种定量测量。

没有独立重复实验时不虚构样本量、误差条或显著性检验。单点、范围、上界、图中估读与原文精确标量分别标记；本阶段不新增图像数字化工具，不默认为范围中点进行定量排名。条件相容但点数不足时只展示差异，不声称可靠趋势或因果关系。

## 11. 报告和完成判据

最终报告包含原问题与纳入范围、数据库计算属性、文献身份及预览决定、实验提取与证据、统计与可比条件、综合判断、必需指标覆盖和未解决事项。预览发现、作者主张、直接实验事实和系统推断分别表达。

两个维度独立表示：执行是否已经结束，以及科研问题回答是否完整。报告已生成并不意味着材料已验证。

- 有可靠数据且所请求分析执行完毕：可以记录工程链路完成；pending 数据仍醒目标明“待审核试运行”。
- 缺少关键指标、条件或仍有论文未处理：科研覆盖为 partial，明确哪些阶段成功、哪些结论不能给出。
- 没有可安全统计的数值：跳过统计，保留定性证据及缺项，不能宣称实验分析完成。
- 缺少全文：停在 waiting_fulltext，给出阶段性结果，而不是已完成全文报告。

报告、数据集和统计结果引用必须属于当前任务及选定提取快照。禁止通过修改题目、复用其他主题报告或静默载入旧矩阵来形成成功外观。

## 12. 兼容性与实施范围

主要衔接位置是 master 的任务契约/状态/上下文/runner/nodes、服务器附件注册、正常 CLI 工厂、统一网页分发、文献阶段适配器和试运行测量交接。具体文件拆分在后续实施计划确定，不把所有能力堆入网页分发函数。

原 Master 无附件输入兼容，原单独文献交互兼容，现有已保存报告复用作为独立入口保留。新任务按快照接续，不用模糊主题文本寻找缓存。启动时没有 pgvector 或配置不完整，元数据能力仍可用；全文阶段明确说明不可执行，不降级成无来源测量。

网页、Excel、Word 的可选依赖完整性单独验收。既有环境失败记录保留，不修改断言来制造通过，不在设计阶段安装依赖。稳定验收需要使用实际网页运行环境，不能仅凭无界面路由测试确认网页可用。

## 13. 分阶段验收

实施先验证附件与主控任务接续，再验证预览决定，随后验证提取快照、试运行交接、条件统计和汇总。每一阶段有失败用例和回归，不一次扩大所有生产能力。

必须覆盖：

- 无主题上传仍只预览；用户只要预览时不启动提取；单独文献模式保持选择性详细分析；
- 明确的端到端请求上传后能自动接续，原任务与已完成数据库结果保持；
- 只有附件无新文字、“继续”、“第2篇”等指代正确；多任务歧义、用户换题和取消安全处理；
- 再次进入或服务重启不会丢失有效附件/阶段；非法或跨会话引用拒绝；
- 不相关、混合体系、缺少必需指标、扫描/损坏 PDF、无数值、缺条件、源读取失败与限流有明确状态；
- 并行提交遵守现有会话锁，成功阶段幂等，失败阶段可有界重试，不扩大调用额度；
- 对照/异质结/复合/纯相身份不混淆，背景引用不进入主实验统计；
- pending 能安全试运行但不自动 approved，正式入口仍拒绝 pending；
- 旧报告、矩阵、审核、源片段和 v18 冻结记录保持，复用与本轮新提取如实区分；
- 从本轮数据集独立重算统计，确认分组键、输入行和报告引用一致。
