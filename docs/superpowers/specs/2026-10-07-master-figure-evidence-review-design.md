# 主控全文任务中的待核对图证据设计

日期：2026-10-07。类型：架构扩展。版本：figure-evidence-review-v1。

状态：用户已以“确定”批准聊天中的第一版范围。本文是对该范围的书面细化，等待用户审阅；尚未实施，不代表正常链路或稳定验收通过。

## 1. 目标与已批准边界

第一版采用人工指定页码和图区域、本地文字识别、人工核对的方案。在文献详细提取完成后、任务级数据分析前，提供独立图证据核对环节。

用户可以查看完整来源页及局部原图，修订识别文字、确认文字或跳过。原始识别结果不覆盖，修订和确认另存，并绑定当前任务及原 PDF。

图中文字核对与实验条件确认是两件事。第一版仅实现前者；界面明确显示“实验条件尚未绑定”。即使用户确认图轴显示到 180 分钟，也不会把所有测量的时间改为 180 分钟。

未确认、跳过或识别失败时，原有安全数据分析和带缺失说明的报告仍可继续。所有图信息仅进入单独的证据附录，不改变测量条件、审核状态、分组、排名或统计。

不纳入：自动发现所有图片、自动识别面板和样品身份、图线数字化、降解率估读、跨图表测量终点绑定、自动化学式纠错、远程图像模型、实验数据库 Agent、后台扫描或自动正式验收。

## 2. 方案与当前依据

已讨论三个方案：

1. 人工指定区域加本地识别：有明确来源边界，可人工修订，选为第一版。
2. 自动定位所有图再识别：需额外验证页布局和面板归属，不在本版实现。
3. 远程图像模型识别：需要新的图像外发权限及服务验证，不在本版调用。

依据是现有源码和本地 phase5E spike，后者不是生产代码。现有 `FulltextTask` 保存任务阶段及附件，`ArtifactRegistry.resolve_pdf` 校验会话和文件身份，提取快照及 `FulltextAnalysisStore` 使用不可变引用。提取处理器当前在试运行交接后直接调用分析处理器，尚无图证据确认入口。

phase5E 仅测试人工指定区域的 7 个本地输入。时间轴大部分可读，但标题首字符错误、180 被拆词；图例的化学式和百分号错误明显。因此不能把本地 OCR 视为可信的结构化事实，也不能证明自动定位或稳定读取能力。该 spike 的临时代码不得原样接入生产。

## 3. 用户交互

功能默认关闭。启用后，只对启用该功能的新主控全文任务，在当前选定论文提取完成且尚未运行任务级统计时开启一次核对批次。单独文献模式和已有任务不自动增加该步骤。

核对入口展示当前任务原问题和可选论文。论文必须属于当前会话授权的附件、预览决定为 extract，且有已完成的本任务提取快照；不能从历史库自动追加论文。

用户操作顺序：

1. 选择论文及一基页码，查看来源页。
2. 输入图号或面板标识作为人工定位说明，在页面上选择矩形区域。
3. 点击本地识别；原图、原始识别文字、识别失败信息和可修订文字同时显示。
4. 选择文字类型：时间轴文字、时间轴刻度、图例文字或其他图中文字。原始和修订内容始终作为文字保存，不自动转换成实验时间或材料身份。
5. 点击“确认文字”“跳过此图”或“重新选区域”。确认失败识别也允许手工转录，但必须保留 OCR 失败状态和人工转录标记。
6. 点击“完成核对并继续”关闭本批次，恢复分析；若没有需要核对的图，点击“跳过图证据并继续”。尚未决定的图会明确列出，不能静默确认；用户可一次性明确选择“跳过剩余并继续”。

“确认文字”仅表示当前操作者核对了可见图中文字，不等于专家批准，也不等于样品身份或实验条件绑定。界面不提供“全部实验条件已确认”按钮。

普通聊天中的“继续”“确定”“都正确”等模糊话语不能批准图证据，只返回核对入口提示。决定通过显式、任务绑定的结构化操作提交；模型输出和 PDF 内容均不能触发确认。

## 4. 模块边界与接入

新增独立图证据模块，分为契约、来源渲染、可选本地 OCR、不可变存储和核对服务。网页只负责输入及展示，不能直接改任务阶段、来源哈希或审核字段。

- 来源渲染：复用 `ArtifactRegistry.resolve_pdf`，根据授权 PDF、页码和矩形产生来源页及局部图，不接受客户端任意文件路径。
- OCR：定义可替换的本地接口，提供支持时调用 Windows.Media.Ocr；依赖或语言不可用时返回 unavailable，仍支持原图及人工转录。
- 核对服务：负责候选来源验证、修订、显式确认、跳过、批次关闭、并发与幂等。
- 主控接续：在 `FulltextExtractionProcessor` 结束后、`FulltextAnalysisProcessor` 调用前加入核对闸门。原有快照和 trial 交接可以已保存，但本任务的统计尚未启动。
- 报告：`FulltextAnalysisRecord` 仅新增可选图证据批次引用，正文附录根据该引用读取核对状态；不将图文本写入 trial 数据列。
- 入口：在 `MasterAgentRunner` 提供 UI 无关的结构化核对入口，网页和 CLI 共享服务；主控聊天入口只提示或恢复，不解释自然语言来代替核对操作。

预计涉及 `fulltext_tasks.py`、`fulltext_extraction.py`、`master_runner.py`、`fulltext_analysis_contracts.py`、`fulltext_analysis.py`、`ui_controller.py`、正常 CLI 工厂与 `unified_ui_gradio.py`，以及新增的独立图证据模块和对应测试。最终文件拆分在实施计划细化，不把存储及权限逻辑堆入网页。

## 5. 来源和不可变记录

批次绑定 conversation_id、task_id、当前附件及选定提取快照引用、策略版本。每个候选至少记录：

- 服务器生成的候选 ID、父修订引用、创建时间；
- 文档 ID、附件 ID、PDF SHA256、快照 ID及摘要；
- 一基页码、页面尺寸及旋转信息；
- 用户提供的图号或面板说明及 human_selected 标记，不假称已自动核实；
- 原页坐标中的矩形、显示坐标转换、渲染参数、渲染器版本；
- 受控局部图引用及 SHA256、来源页渲染引用；
- OCR 引擎和语言、状态、原始文字及词坐标；
- 用户文字修订、文字类别、操作时间和当前会话操作者标记；
- text_review_status：pending、text_verified 或 skipped；
- condition_binding_status：第一版固定为 unbound。

OCR 状态与审核状态独立：识别失败不代表没有图中文字，文字核对通过不代表 OCR 自身合格。无 OCR 的手工转录显式标记 manual_transcription。

原始候选、图像及每次修订都不可变。任务仅指向当前批次修订的 ID 和内容哈希，修订带父引用。重新选择区域产生新候选，旧候选保留并标记被替代，不覆盖旧文字。存储采用限长、严格字段和哈希校验；不能只保存本地图片路径或网页 state。

## 6. 阶段、恢复及幂等

新增 `awaiting_figure_review` 阶段及可选图证据策略、批次引用。仅首次进入的新任务记录策略；旧任务字段缺省为 disabled，不随进程开关改变。

正常路径为：完成提取及已有交接 -> awaiting_figure_review -> 明确完成或跳过核对 -> analyzing/reporting -> finished。

主控当前的通用接续会重设为 previewing，实施时必须先识别图核对阶段并保留其状态；不能让“继续”绕过图核对，也不能重新执行已完成数据库、检索、预览或提取。预算暂停和取消复用 ready_to_resume，但 resume_stage 必须指向真实未完成阶段。

确认和批次关闭使用现有会话锁，同时校验客户端期望的批次/候选修订摘要。过期或并发决定拒绝并刷新当前状态，不最后写入覆盖先前决定。重复相同操作返回已保存引用；重复“继续”不重新渲染、识别或执行已完成阶段。失败 OCR 仅用户明确重试时发起新尝试。

当前原始问题、选定附件或快照变化时，旧核对不能移用到新来源；仍保留旧修订，并要求新批次显式决定。已结束任务不自动重新开启核对，用户需明确创建新任务，不修改旧报告。

禁用开关只影响新任务。已开启且正在核对的任务仍需可明确跳过；OCR 不可用不得使任务永久无法退出。

## 7. 权限、失败处理及资源限制

每次打开、修订、确认及恢复都验证当前会话授权、task_id、附件身份、快照归属、PDF 哈希和图像哈希。跨会话、过期候选、非选定文档、源内容改变或损坏引用不允许确认或进入报告的已核对部分。

客户端只传受控标识、页码、矩形、文字和决定。矩形须有限数值、面积为正且在页面内；屏幕坐标由服务器依据实际显示尺寸、缩放和旋转映射，不能混用 OCR 像素和 PDF 页坐标。修订文字按纯文本显示，转义 HTML/Markdown 的可执行内容；PDF 及 OCR 中的指令一律作为证据文本，不作为主控指令。

默认有界限制：每任务最多 20 个活跃候选、最多 100 次图证据修订；页码不超过授权 PDF 的真实页数；图号说明最长 160 字符；单候选原始 OCR 文字及修订文字各最多 10000 字符；单批次 JSON 最大 2 MiB。展示整页默认 150 dpi，局部图最多 300 dpi，单次渲染最多 400 万像素、单图片最多 10 MiB；同时遵守 OCR 引擎实际最大尺寸，不硬编码为某次 spike 的值。

本地 OCR 设置 30 秒超时，任务取消后不启动下一次渲染或识别。支持时使用后台无窗口子进程，不弹出交互窗口。不安装语言包或 OCR 软件，不发送任何图像到远程服务。无法满足限制时给出明确原因，用户可缩小区域、手工转录或跳过。

渲染或 OCR 失败不伪造空白成功；原图可读时允许手工转录。源文件或来源完整性失败时不能确认，保留错误说明，并允许明确放弃该证据后生成 partial 报告。失败隔离不弱化现有数值来源门槛。

## 8. 分析与报告的强隔离

第一版不更改 ExperimentalMeasurement、样品条件、原矩阵 review_status、共享条件、逐样品属性或 trial 数据集。图证据不是统计输入，即使文字已核对也不参与条件合并、趋势、显著性检验或排名。

报告新增“图中文字核对”附录，展示来源、区域、原始识别、用户修订、决定、OCR 可用性和未绑定说明。修订文字表述为“用户核对的图中文字”，不是“作者已报告的测量条件”或“专家审核通过”。pending、skipped、unavailable 及来源失败分开列示。

完成核对或跳过后仍使用现有数据集和隔离规则。图证据不足时科学覆盖仍为 partial，未知条件仍是未知。图证据确认不会使一个 partial 报告变成科研正确性或稳定验收通过。

## 9. 兼容与启用策略

正常工厂拟增加 `MASTER_FIGURE_EVIDENCE_REVIEW`，默认 false，不依赖或自动开启 shared/targeted 条件开关，不修改现有 `.env`。

旧任务、旧分析记录的可选字段使用兼容默认值；读取不触发批量迁移、不改旧哈希，也不重写旧报告。开启策略属于任务创建时的配置，不能在已完成分析上追加图核对并宣称原运行涵盖新能力。

Windows OCR 仅是可选适配器，核心契约、来源检查、确认及跳过不依赖 Windows。测试使用明确标记的本地替身验证控制逻辑，实际 OCR 结果另行实测，不能把替身测试计为真实读取合格。

## 10. 验收要求

实施必须覆盖以下验证层次，分别记录结果，不混为正式全链通过：

1. 契约和安全：非法页码、非有限或越界矩形、跨会话候选、错任务/文档/快照、源或图像篡改、超长文字、过期决定均拒绝；用户输入不能覆盖服务器来源字段。
2. 核对规则：普通“继续”不批准；只有显式确认记录 text_verified，condition_binding_status 始终 unbound；人工修订保留原始 OCR；跳过剩余须显式；模型文字不能确认。
3. 恢复：服务重启能恢复有效批次；重复操作不重复 OCR；并发或过期修订不覆盖；取消、失败、有界重试和禁用新任务开关均有可退出路径。
4. 兼容：旧任务默认 disabled，旧报告可读且不重写，单独文献模式不受影响；禁用时正常主控路径维持原行为。
5. 统计隔离：核对前后数据集内容摘要、测量时间、样品变量、审核状态、分组和独立统计结果完全一致。故意确认错误图文字也不能改变统计输入。
6. 本地真实案例：通过授权 PDF 的手选页/区域完成识别、修订、确认和跳过，保留来源页及局部图。验证点是流程和隔离，不要求 OCR 凭空达到正确化学式识别。
7. 正常入口：新主控任务进入等待核对，显式完成后继续原有部分报告；真实网页和 CLI 分别验证，不能用界面加载或仅无界面调用代替实际网页交互。

开发记录与正式稳定验收分离，不改写既有 45 条 NOT_RUN 观察，不覆盖原 PDF、旧矩阵和冻结结果。新增功能通过后仍需单独进行完整链路验收；本文不承诺材料专业判断正确。
