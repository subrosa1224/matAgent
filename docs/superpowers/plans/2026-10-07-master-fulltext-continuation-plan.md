# 主控全文接续实施计划

依据：用户已批准 `docs/superpowers/specs/2026-10-07-master-fulltext-continuation-design.md` 并要求“按设计实施”。writing-plans 技能当前未提供，采用手工计划；不安装额外技能，不再重复请求已批准的设计权限。

## 实施顺序

1. **附件与任务基础**：扩展 ArtifactRegistry，持久化安全附件目录与会话授权；新增严格全文任务契约与选择/恢复规则。在主控 checkpoint 内保存原任务及已经完成的结果引用，兼容无附件接口。
2. **入口接续**：增加主控安全附件引用输入、会话内绑定和选择；统一页面及 CLI 接入同一主控，保持单独文献模式和无主题上传预览。缺少处理能力时显示真实的不可执行状态，不模拟提取成功。
3. **文献阶段**：复用解析/索引/预览服务，返回结构化决定，按原任务与用户最新指令选择深度分析；保存预览阶段并测试中断与重启。
4. **新提取与交接**：显式执行通用矩阵提取，写不可变任务快照，不覆盖既有矩阵；复用证据检查函数，注册 trial 数据集，保留原审核状态、源引文和隔离理由。
5. **统计与汇总**：由数据分析 Agent 使用任务专属数据集，条件隔离、缺项降级、分来源汇总；预览与摘要不作为实验数值输入。
6. **真实验证与冻结**：先使现有网页与可选文档依赖完整，再用 N02/N04/N08 原题、原追问、指定 PDF 走正常入口，独立验证统计、复用和旧数据保护。随后才做重复稳定验收。不得填改 v18 正式账本。

每个阶段先补失败测试，再实现最小改动、定向回归及静态检查；发现问题先按 systematic-debugging 定位。无须新增专业人员实验数据，试运行不代表专业验证。

## 第一阶段测试范围

- PDF 注册元数据不暴露路径；原独立注册/数据文件功能兼容。
- 注册器重建后能解析同一附件，并核对 PDF 头、文件大小和 SHA256。
- 所属会话在服务器持久化，未知/跨会话/非法引用拒绝。
- 文件被替换、授权目录被绕过、目录记录损坏时失败关闭。
- 原任务、原问题、已完成查询与分析引用严格保存，任务不能跨会话选择。
- 多个活动任务时不猜测；指定任务可恢复；完成任务不被“继续”自动重跑。
- 主控 checkpoint 保存任务并随原会话恢复，旧无附件请求不受影响。

## 验证与保存

定向测试结果使用新的工作输出目录，不覆盖 v16/v17/v18 报告、旧测试 XML 或冻结记录。只检验源文件身份的测试不构成论文事实复核。测试替身只用于单元/路由测试；真实全文验收不允许用观察器代替处理响应。

实际生产代码修改后不能继续声称源码与 v18 相同；保留 v18 文件原样，后续新冻结单独记录指纹。每阶段交付说明已完成、未完成、失败或未执行的验证，不能将局部通过报告成完整链路通过。

## 当前进度

第一、二阶段已实现并完成定向回归：

- 安全 PDF 注册目录与会话授权持久化；恢复时复查目录、文件大小和内容哈希，损坏索引返回安全错误，不扫描历史目录猜测文件。
- 原问题、当前轮结果引用、后续指令与任务阶段保存在主控 checkpoint；多任务需要指定服务器任务 ID，跨会话、损坏状态及取消输入失败关闭。
- 自动页面的活动任务上传/指代优先接续同一主控；首次科研问题与 PDF 同时提交也进入主控。无主题且无任务上传，以及显式文献模式，仍保持独立预览。
- CLI 增加可重复的 `--pdf` 和 `--task-id`，流式及非流式入口一致；无附件调用兼容。首次请求与附件绑定只计算一个用户轮次，保留第一阶段回答、证据引用和调用计数。
- 上传前后提出的“只预览”“只分析第2篇”等指令都会保存；当前仅保存约束，第三阶段才执行范围决定。取消不显示为完成。

验证：主控单元回归 276 项通过；既有页面路由兼容回归 18 项通过、19 项未选入；涉及的生产文件与新增测试静态检查通过。292 个旧基线受保护文件哈希未改变。结果保存在 `outputs/fulltext_continuation/2026-10-07/phase2/`，没有填改正式 45 条验收记录。
