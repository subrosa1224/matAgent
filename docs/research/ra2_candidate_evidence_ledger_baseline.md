# RA-2 候选、材料身份与 Claim–Evidence 账本基线

> 日期：2026-09-02  
> 状态：工程验收完成  
> 前置条件：RA-0A、RA-1 完成；RA-0B 专业金标并行待审  
> 对应路线：`docs/research/end_to_end_research_task_plan.md`

## 1. 本阶段完成范围

RA-2 建立了跨数据库、文献和用户数据共享的项目对象及不可变账本，但尚不自动运行三个
子 Agent。完成内容包括：

1. 标准化候选 `MaterialCandidate` 和逐属性 `PropertyValue`；
2. 候选硬条件状态、淘汰原因、排序组成、证据状态和候选等级合同；
3. 数据库、文献全文、文献摘要、用户实验和数据分析五类 `ScreeningEvidence`；
4. 结构化来源定位，包括 query/material ID、document/chunk/page、dataset/analysis ID；
5. `ScreeningClaim`、支持/反证/背景关系和 Claim–Evidence 引用；
6. 材料身份记录、确定性身份解析规则和可审计身份评估；
7. 候选、证据、身份、Claim、关联和决定的追加式不可变存储；
8. MaterialsDatabaseAgent、LiteratureAgent 和 DataAnalysisAgent 的三个只读规范化适配器。

## 2. 材料身份规则

当前解析器严格执行以下层级：

- 同一来源且材料 ID 相同：可作为精确身份；
- 跨来源规范化化学式、空间群和结构指纹均一致：可作为同一结构候选；
- 化学式相同但空间群不同：强制标记为不同物相并阻止属性合并；
- 只有化学式、材料家族、元素体系或名称相同：最多作为背景，不可支撑候选属性；
- 高压、温度或样品条件不同：即使身份可关联，仍保留属性可比性复核要求。

RA-0 的 20 个身份边界案例全部通过确定性测试。待专业审核的“同化学式不同空间群”案例
仍保持专业金标待审状态；工程规则只确保系统不会错误合并它们。

## 3. 证据与 Claim 门禁

- 候选的每个属性值必须引用账本中的结构化证据；
- 候选属性的值、单位和 property ID 必须与证据完全一致；
- 未登记属性不能进入候选、证据或 Claim；
- 数据库计算属性、数据库元数据、全文实验、摘要背景、用户实验和分析结果保留不同角色；
- 文献全文证据必须具有 document、chunk、页码、原文片段和文本哈希；
- 待审或已拒绝证据不能支持或反驳 Claim；
- 文献和用户实验要支撑候选结论时，必须引用已保存的材料身份评估；
- 只按化学式或名称建立的背景映射不能提升为候选属性证据；
- 需要专业复核的身份，在复核完成前不能支撑候选结论；
- 跨候选证据不能进入另一候选的决定；
- 同一账本 ID 只能保存一次，相同内容可安全重试，不同内容不能覆盖。

## 4. 三个只读适配器

`MaterialsDatabaseReadAdapter` 将已有 `QueryResultReference` 转为候选和逐属性证据，保留
query ID、material ID、数据库版本、单位和属性科学边界。未登记字段被跳过并产生警告。

`LiteratureEvidenceReadAdapter` 只接收已有实验组和结构化测量。它保留样品、实验条件、
页码、chunk、原文和审核状态，不会从自由文本猜测未登记属性，也不会自行决定材料映射。

`DataAnalysisReadAdapter` 只把已有 `AnalysisResult` 注册为分析证据，保留 dataset ID、
analysis ID、方法、参数和摘要；它不会把统计摘要自动改写成候选材料属性。

三个适配器均没有数据库查询、全文检索、模型调用或原始记录修改接口。

## 6. 保留限制

本阶段没有实现：

- 自动调用三个子 Agent 的工作计划和重试；
- 数据库查询后的完整候选漏斗；
- 属性方法、样品形态和实验条件的可比性计算；
- 支持、冲突和不可比较的科学综合；
- A/B/C/D 等级的自动判定；
- 最终科研报告或新用户界面。

因此 RA-2 完成不表示已经能自动完成端到端科研任务。它提供的是后续编排和科学综合不会
丢失身份、来源和证据边界的可信数据底座。
