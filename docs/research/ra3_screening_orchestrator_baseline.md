# RA-3 ScreeningOrchestrator 与候选漏斗基线

> 日期：2026-09-03  
> 状态：工程验收完成  
> 前置条件：RA-0A、RA-1、RA-2 完成；RA-0B 专业金标待审  
> 对应路线：`docs/research/end_to_end_research_task_plan.md`

## 1. 本阶段完成范围

RA-3 建立了项目级、可恢复且有资源上限的候选筛选编排核心。它只执行用户已经确认的
筛选合同，不负责产生 RA-4 的科学综合结论，也没有提前改造最终界面。

本阶段完成：

1. 将确认后的项目合同固化为带稳定 ID 和依赖关系的八个工作项；
2. 通过现有 MaterialsDatabaseService 生成候选并写入 RA-2 账本；
3. 在编排层重新执行全部材料范围与硬约束，不直接信任上游返回顺序；
4. 对通过硬约束的候选执行确定性、可解释的加权排序；
5. 按项目上限选择 shortlist、快速文献核验和全文核验候选；
6. 通过 LiteratureReviewPort 和 CandidateAnalysisPort 调用受约束的领域能力；
7. 保存每个工作项的状态、尝试次数、输出引用、错误和项目进度；
8. 失败时暂停并保留已有候选与证据，重试只恢复失败工作项；
9. 同一工作 ID 复用幂等键，已完成工作不会因续跑而重复执行；
10. 每个项目最多允许一次有明确目标的补充文献核验；
11. 候选最多 500 个、shortlist 最多 100 个、快速核验最多 20 个、全文核验最多 5 个；
12. 编排结束状态为 `evidence_ready`，不会在尚未综合时冒充科研任务已经完成。

## 2. 候选漏斗规则

固定工作链为：

```text
数据库候选
  → 本地硬过滤
  → 可解释排序
  → 快速核验候选选择
  → 快速文献核验
  → 全文核验候选选择
  → 全文文献核验
  → 可选候选数据分析
```

硬过滤逐条处理组成范围和 `hard_filter` 条件，并保存 `passed`、`failed` 或 `unknown`
以及结构化原因。缺失值严格执行项目合同中的排除、保留并警告或项目失败规则，系统不会
为了产生结果而自动放宽阈值。

排序只读取账本中带证据引用的候选属性。每项 `soft_rank` 条件具有显式正权重，分数及其
组成一并保存；并列时按稳定材料 ID 排序，因此同一快照和合同可重复得到相同结果。

## 3. 失败恢复与幂等性

- 每次运行绑定完整项目合同哈希；项目被修改、未确认或确认修订不一致时拒绝执行；
- 运行状态采用不可变 revision 保存，并用期望 revision 防止旧状态覆盖新状态；
- 工作开始、成功、跳过和失败均写入持久状态；
- 数据库候选适配器为工作 ID 保存规范化结果缓存；
- 失败续跑保持候选与证据引用不变，已完成数据库查询不会再次执行；
- 文献失败重试使用相同幂等键，且受每项最多两次尝试的限制；
- 初始漏斗结束后只允许增加一个 supplemental work item。

## 4. Benchmark V1 工程验收

三个端到端任务草案均在冻结的 300 条 Materials Project 快照上形成了精确、可复现的
候选漏斗：

| 任务 | 通过硬约束并进入排序 | shortlist |
|---|---:|---:|
| 稳定宽禁带氧化物 | 83 | 10 |
| Fe2O3 同化学式多晶型比较 | 26 | 26 |
| 亚稳候选筛选 | 58 | 10 |

三项任务的完整排序材料 ID 和 shortlist 均与当前 Benchmark V1 参考答案逐项一致；进入
排序及 shortlist 的已知硬约束违规候选为 0。快速核验和全文核验调用分别保持在 20 和 5
的上限内。零结果反例不会放宽合同，也不会调用文献核验。

需要严格区分：这些结果证明的是工程银标一致性。三个任务仍标记为
`draft_pending_*_review`，不能替代 RA-0B 的材料领域专业审核。

## 6. 尚未完成与边界

- 真实 MaterialsDatabaseService 已有执行适配器；LiteratureAgent 和 DataAnalysisAgent 当前
  通过明确端口接入，编排行为已用受控实现验收，但尚未接入最终用户界面；
- RA-3 只形成候选、淘汰、排序和分层核验记录，不判断跨来源数值是否可比；
- 尚未生成支持、冲突、不可比较、证据不足等科学综合判断；
- 尚未形成 A/B/C/D 候选等级、验证方案或科研报告；
- 进程在外部查询已经完成但幂等缓存尚未落盘的极短窗口内崩溃时，外部服务级去重仍需
  后续加固；当前可保证正常续跑和已缓存重试不重复；
- 现有 CSV 数据分析功能保持原样，RA-3 没有删除或替换它。

因此，RA-3 完成并不表示产品已经可以交付完整科研任务。它完成的是三个子 Agent 之间
共享的、有状态候选漏斗骨架。
