# Intern 模型连接策略

Intern 的主控/子 Agent 和结构化输出调用统一使用以下连接策略。它不改变 Windows 代理，也不影响 Materials Project、文献检索等其他服务。

- 默认直连：`INTERN_USE_SYSTEM_PROXY=false`。只有确实需要系统代理时才设为 `true`。
- 保留 HTTPS 证书和主机名校验，并保留 `SSL_CERT_FILE` / `SSL_CERT_DIR` 指定的信任配置。
- 仅连接失败和超时重试同一个模型请求，不重复执行数据库工具、其他工具或整个 Agent 任务。
- 默认总共尝试 2 次；`AGENT_MODEL_MAX_ATTEMPTS` 控制 Agent，`LLM_MAX_ATTEMPTS` 控制结构化输出。范围均为 1–3，设为 1 可关闭重试。
- 关闭 SDK 内置重试，避免叠加。两次尝试之间等待 0.5 秒；配置 3 次时第二次间隔为 1 秒。
- Agent 每次请求超时使用 `AGENT_MODEL_TIMEOUT_SECONDS`（默认 120 秒），结构化输出使用 `LLM_TIMEOUT_SECONDS`（默认 45 秒）。这是 HTTP 各阶段的超时，不是整条任务的严格总时限。
- 认证、参数、限流、服务端状态错误及输出格式/校验错误立即返回，不在连接层重试。
- 故障日志仅记录错误类型和尝试次数，不记录密钥、原始请求、模型内容或异常原文。Agent 的持久化错误保留原因类型链。

连接中断后，服务端是否已生成答案无法确定，所以重试仍可能额外消耗模型额度；这不影响本地工具只执行一次的边界。

## 验证范围

`tests/unit/test_intern_transport.py` 使用模拟网络验证上述边界，不调用真实服务。真实请求的小样本成功仅证明本次连接可用，不代表整套科研系统或稳定验收已通过。

生产代码变更后，冻结验收需创建新基线；保留之前失败的基线，不用新代码覆盖旧结果。
