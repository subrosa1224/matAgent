# 全文自动分批处理（2026-10-08）

## 问题与限定设计

原全文处理共享 55 秒软预算，涵盖索引、预览、提取和分析；请求超时沿用普通模型的 45 秒。模型调用次数耗尽也会暂停。因此一次上传十几篇，即便单次请求没有超时，也无法靠单纯提高请求超时完成。

保留现有逐篇校验、任务保存与快照接续，不用重复提交用户消息、重写科研问题或无限重试解决。用户已批准自动有界分批，先完成选定论文预览，等待确认，再进入详细提取与分析。

## 改动

- 仅正常全文入口启用自动分批。每批默认 600 秒软预算、6 次模型调用，最多 40 批。单独全文请求默认 120 秒；普通请求仍为 45 秒。均可配置，非法配置拒绝启动。
- 只有三个明确的预算暂停代码触发自动接续。真实服务失败、来源校验失败、等待用户输入、缺失处理器、取消都会停止。连续无任务进展也停止。
- 每批保留同一用户轮次、原问题与真实指令；返回调用计数累计实际执行，初始数据库/文献检索链的剩余额度不替代全文独立批次预算。
- 每篇新预览记下确认指令边界；原问题中的“提取/分析”不能替代用户读过新预览后的选择。新增“确认分析/开始分析”识别，保留原有序号、排除与重试后的重新确认规则。
- 进度在成功保存后发出，进入现有页面进度区；不输出论文正文或技术来源参数。后台处理所有权保留到安全停止点，避免取消后两个写入者同时修改同一任务。
- 一次最多选 20 篇的既有限制仍在；不是无限数量上传支持。预算是安全点检查，不会强行终止 PDF 索引或正在进行的远程请求。
