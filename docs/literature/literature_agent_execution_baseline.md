# LiteratureAgent 执行基线（唯一实施依据）

> 文档状态：已确认并执行  
> 版本：v1.0  
> 日期：2026-08-20  
> 适用范围：`materials-screening-core` 的文献检索与知识整合子智能体  
> 优先级：本文件用于约束后续实施顺序、完成定义和范围变更；若与
> `literature_agent_design.md` 中的进度描述冲突，以本文件为准。

## 1. 为什么需要这份基线

当前项目已经实现了不少底层组件，也完成了三篇论文的人工校准，但“组件可用”不等于
“用户提出一个主题后，智能体可以自动交付完整文献报告”。此前把这两种完成状态混在
一起，导致项目看起来一会儿接近完成，一会儿又像刚起步。

从本文件确认之日起，LiteratureAgent 只按阶段门推进。未通过当前阶段验收前，不提前
开发下一阶段，不用手工处理更多论文来代替通用能力建设，也不把实验性命令描述为已完成
功能。

## 2. 最终产品目标

LiteratureAgent 的最终职责不是“分析一篇论文”，而是把用户的研究问题转化为一份
可核验的文献知识结果：

```text
用户研究问题
  → 检索词扩写
  → OpenAlex + Semantic Scholar 多源检索
  → 去重、排序、候选文献清单
  → 对可获得全文的论文进行 PDF 摄取与 RAG
  → 单篇论文档案 + 实验对比矩阵
  → 摘要主张与正文证据核验
  → 跨论文归纳、分歧与适用边界
  → 带来源、页码和审核状态的中文整合报告
```

系统必须支持两种用户入口：

1. **主题入口**：用户说“帮我找某材料/性能/工艺方向的文献”。系统先返回可靠的候选
   文献集合，再对具备全文的论文继续分析。
2. **PDF 入口**：用户提供已有 PDF。系统直接入库、分析并生成待审核结果，不要求用户
   先懂得如何检索文献。

最终输出遵循以下业务结构：

```json
{
  "papers": [
    {
      "title": "...",
      "doi": "...",
      "year": 2025,
      "key_findings": ["..."]
    }
  ],
  "synthesis_summary": "...",
  "data_tables": ["实验组、变量、测试条件、数值和对比"],
  "kp_edges": ["仅由已批准证据生成的知识关系"],
  "warnings": ["全文缺失、证据不足、论文结论冲突等"]
}
```

对普通用户展示的是中文报告；严格 JSON 作为智能体之间和程序接口之间的数据契约。

## 3. 首个可交付版本的范围

### 3.1 必须实现

- 接受自然语言研究主题、材料关键词、年份范围和期望文献数。
- 自动扩写有限数量的中英文同义词与检索式。
- 同时检索 OpenAlex 和 Semantic Scholar，并跨来源去重、排序和保留来源信息。
- 输出候选论文清单，明确区分“仅元数据/摘要”和“已有全文”。
- 摄取用户提供或项目已授权的本地 PDF。
- 通过 PyMuPDF 分页解析、bge-m3 向量化、pgvector HNSW 检索和 bge reranker 重排。
- 为每篇全文生成单篇档案、实验组/测量值/比较关系和摘要主张核验结果。
- 所有自动抽取内容先进入 `pending`，经过证据校验和人工审核后才进入可信知识层。
- 对多篇已分析论文生成中文综合报告，说明共同趋势、冲突、实验条件差异和局限性。

### 3.2 本版本明确不做

- 绕过付费墙、登录或出版商权限自动下载 PDF。
- 扫描件 OCR、复杂图像曲线数字化和所有版式的通用表格识别。
- 未经审核自动批准 LLM 抽取结果。
- 用摘要替代正文实验数据，也不把作者主张自动当成已证实事实。
- 构建通用知识图谱平台或无限扩展材料领域本体。
- 在通用自动抽取尚未通过验收前继续手工拆更多论文。

## 4. 系统边界与模块职责

| 模块 | 唯一职责 | 不负责 |
| --- | --- | --- |
| Query Planner | 从用户问题生成受限、可记录的检索式 | 调用 PDF 解析或生成结论 |
| Metadata Search | 调用 OpenAlex/S2、规范化、合并、去重和排序 | 猜测全文内容 |
| Document Ingestion | 验证本地 PDF、解析、分块、向量化和幂等入库 | 自动批准抽取数据 |
| RAG Retrieval | 按问题召回并重排有页码的证据块 | 生成无证据的事实 |
| Paper Analyzer | 生成单篇档案、实验矩阵、摘要—正文核验 | 跨论文泛化 |
| Review Gate | 校验证据并记录批准/拒绝与审计事件 | 修改原文或覆盖已批准数据 |
| Synthesis | 汇总多篇已检索/已审核结果，呈现一致与冲突 | 隐藏缺失全文或证据不足 |
| LiteratureAgent | 编排上述模块并返回严格结果 | 绕过阶段、权限和审核规则 |

数据依赖保持单向：

```text
LiteratureAgent
  → Query Planner / Search
  → Ingestion / RAG
  → Paper Analyzer
  → Review Gate
  → Synthesis
  → LiteratureResult
```

综合产品链路尚未完成。**

## 6. 严格实施阶段

任何阶段只有在“交付物、自动测试、人工验收”三者全部满足后才可标记完成。

### P0：冻结现状并建立可信基线

目标：停止扩散，明确哪些功能可用、哪些只是原型。

交付物：

- 列出当前所有 LiteratureAgent 命令、模块、数据表和测试。
- 将 `literature process` 明确标注为实验性，避免用户误认为它已可稳定使用。
- 整理三篇金标的审核状态和基准数据，不再继续手工新增论文。
- 在用户确认的基线修正范围内，补齐现有 2025 生物陶瓷论文的新实验矩阵；这不是
  新增第四篇样本，也不扩展自动抽取功能。
- 运行 LiteratureAgent 相关测试并记录固定基线；项目全量 mypy 的既有错误单独登记，
  不与本子智能体新增错误混淆。
- 形成一份“可用功能清单”和“已知缺陷清单”。

验收门：

- LiteratureAgent 相关离线测试全部通过。
- 本模块新增/修改代码不引入新的 mypy 错误。
- 文档中的每项状态都能对应代码、命令或测试证据。
- 在通过前不开发查询扩写或新的抽取逻辑。

### P1：完成真正可用的文献检索入口

目标：用户只需描述研究问题，就能获得统一、可解释的候选文献清单。

交付物：

- 结构化 `ExpandedQuery`：原始主题、材料名/化学式、同义词、性能/工艺词、最多 6 个
  有界检索式。
- 一个统一检索服务，同时调用 OpenAlex 与 Semantic Scholar。
- DOI 优先的跨源去重、字段融合、确定性排序和统一 `query_id`。
- 用户入口：命令行与 LiteratureAgent 委派均能接受自然语言主题。
- 中文结果包含题名、年份、DOI、摘要可用性、全文状态、入选原因和来源。

验收门：

- 使用 3 个固定开发主题验证，不针对单篇论文写特例。
- 每主题 top-20 中至少有 5 篇经人工判断相关的文献。
- 同 DOI 不重复；来源失败时明确降级；结果可由 `query_id` 重现。
- 用户无需自己构造 OpenAlex/S2 查询参数。

### P2：完成通用的单篇论文档案抽取

目标：任意合规文本型材料论文 PDF，无需编写专用脚本即可生成证据绑定的待审核档案。

交付物：

- 按研究问题、创新、材料、制备、表征、结构、性能、机理、局限和复现参数分任务召回。
- 严格结构化输出；每一项包含文档、chunk、页码、原文短引和风险等级。
- 数值必须在证据原文中出现；未找到则留空，不补写。
- 自动结果只保存为 `pending`，不覆盖人工批准结果。
- 批量显示待审核项，优先展示中高风险项。

验收门：

- 在三篇现有金标上做盲测，不读取人工答案生成自动结果。
- 证据引用可解析率 100%，无原文支撑的数值进入结果数为 0。
- 必要类别的宏平均召回率不低于 80%。
- 人工忠实度平均分不低于 4/5，任一论文不得低于 3/5。

### P3：完成通用实验矩阵抽取与摘要核验

目标：从正文证据中恢复真正可比较的实验设计，而不是只摘一句结论。

交付物：

- 识别对照组、实验组、材料变量、制备/测试条件、指标、数值、单位和不确定性。
- 确定性生成组间比较，禁止 LLM 自行计算无来源数值。
- 从摘要提取作者主张，并与正文测量和比较标记为：支持、部分支持、矛盾或不可核验。
- 缺表格、跨页表格和图中数值分别产生明确 warning。

验收门：

- 三篇金标上的数值精确率不低于 95%，关键实验组召回率不低于 80%。
- 单位保真率不低于 95%。
- 无证据记录进入 `approved` 的数量为 0。
- 摘要主张不得直接生成可信知识边。

### P4：打通用户端到端工作流

目标：将已验收组件编排成真正的 LiteratureAgent。

主题入口流程：

1. 用户输入主题。
2. 系统展示扩写后的检索范围和候选论文。
3. 系统区分摘要可分析、已有 PDF、需用户提供全文三类论文。
4. 对已有全文执行 P2/P3。
5. 用户集中审核待确认项，而不是逐句被迫审批所有低风险内容。
6. 系统生成主题导向的跨论文整合报告。

PDF 入口流程：

1. 用户放入或选择 PDF。
2. 系统完成解析、索引、档案与矩阵候选生成。
3. 系统只要求用户复核证据不足、冲突和中高风险内容。
4. 审批后重新构建正式报告和可信知识关系。

验收门：

- 选择一篇未参与开发的文本型论文，无需改代码、写专用 JSON 或手工 staging 脚本即可
  完成 PDF 到待审核报告。
- 选择一个未参与开发的主题，可完成检索到多篇综合报告；缺全文时正确停在候选清单，
  不伪装为全文综合。
- 所有最终事实均可追溯到论文页码和原文证据。

### P5：正式评测与发布

目标：用固定评测集证明系统达到原始验收要求。

交付物：

- 固定 10 个材料主题、专家相关文献集、关键结论与实验数据金标。
- 离线回归测试、真实 API 集成测试、真实 pgvector/RAG 测试分层运行。
- 部署、模型缓存、数据库备份恢复、常见故障和用户操作说明。

发布门：

- 每个主题召回相关文献不少于 5 篇。
- Recall@20 宏平均不低于 0.70。
- 摘要/综合忠实度人工评分平均不低于 4/5，任一主题不低于 3/5。
- 关键结论证据可解析率和数值溯源率均为 100%。
- LiteratureAgent 相关离线回归全部通过，且不新增项目 mypy 错误。

## 7. 审核与可信数据规则

- 元数据来自 OpenAlex/S2 时保留 Provider 和检索时间。
- 摘要只能支持“论文作者声称”，不能替代正文实验事实。
- PDF 自动抽取结果一律为 `pending`；只有人工批准的数据可生成正式 `kp_edges`。
- 每个数值必须绑定 `document_id + chunk_id + page + source_quote + hash`。
- 证据冲突时并列保留，不自动选择更“合理”的结果。
- 审核采用风险优先的批量方式：低风险可集中确认，中高风险逐项展示；正式发布前不启用
  无人自动批准。
- 已批准数据不可被自动任务覆盖；修改必须产生新的审计记录。

## 8. 防止偏航的变更规则

1. **单阶段原则**：任何时刻只允许一个阶段处于进行中。
2. **先验收后前进**：没有验收记录，不得把阶段标为完成。
3. **禁止用手工样本代替产品能力**：三篇论文只作为金标，不继续用专用脚本堆功能。
4. **范围变更先改文档**：新增 OCR、自动下载、图表数字化等能力，必须先说明必要性、
   成本和对当前阶段的影响，并由用户确认。
5. **状态只有一个来源**：后续进度以本文件第 10 节为准，旧里程碑不再单独宣布完成。
6. **完成措辞统一**：`已完成` 仅表示通过阶段验收；`部分完成` 表示组件存在但产品链路
   不闭合；`实验性` 表示不可承诺用户稳定使用。
7. **不夹带重构**：除非当前阶段验收所必需，不修改其他子智能体或全项目架构。
8. **每次变更小步提交**：一次只解决一个可验证问题，并提供测试结果与剩余缺口。

## 9. 每轮工作的固定汇报格式

以后每轮实施只汇报以下五项：

```text
当前阶段：P?
本轮目标：一个明确目标
完成内容：实际落地的代码/文档
验证证据：执行的测试、样本和结果
剩余缺口：距离本阶段验收门还差什么
```

如果本轮发现新问题，但它不阻塞当前阶段，只登记到缺陷清单，不立即扩展范围。
